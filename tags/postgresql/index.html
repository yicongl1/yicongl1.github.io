关系库里的 JSON 列：什么时候值得把发票和评论塞进数据库

项目代码与报告：https://github.com/yicongl1/Vehicle-Share-Database 上一篇讲的是 vehicleShare 的关系模型：18 张表，保险、发票、评论各自独立。课程的最后一个交付要求做一版 NoSQL 演进，我们选择保留 PostgreSQL，只把三类“整块读写”的数据改成 JSON 列： Vehicule.contrat_assurance Contrat_location.commentaire Contrat_location.facture 对应的 Contrat_assurance、Commentaire、Facture 三张表被删掉。表少了，查询写法变了，代价也随之出现。这篇把这笔账算清楚。 原来的三张表长什么样 关系版里，保险合同、发票、评论都是独立实体： CREATE TABLE Contrat_assurance ( id_assurance SERIAL PRIMARY KEY, nom_assurance VARCHAR(255) NOT NULL, type VARCHAR(255) NOT NULL, vehicule VARCHAR(255) NOT NULL, FOREIGN KEY (vehicule) REFERENCES Vehicule(immatriculation) ); CREATE TABLE Facture ( id_facture SERIAL PRIMARY KEY, date DATE NOT NULL, kilometrage INT NOT NULL, carburant FLOAT NOT NULL, moyen_paiement VARCHAR(255) NOT NULL, montant FLOAT NOT NULL, contrat_location INT NOT NULL, FOREIGN KEY (contrat_location) REFERENCES Contrat_location(id_contrat) ); 它们的共同点：和父记录是一对一或“一合同一份”的关系，读取时几乎总是整块取出，很少单独按发票字段做连接。 这正是 JSON 列的适用场景。 改完之后 保险变成车辆行里的一列：

从 UML 到 BCNF：车辆共享数据库的 18 张表是怎么定下来的

项目代码与报告：https://github.com/yicongl1/Vehicle-Share-Database 车辆共享平台 vehicleShare 的业务听起来不复杂：车主发布车辆，租客预订，取车还车，最后开票。但真正落到关系模型里，会冒出一连串问题：个人、企业、企业司机算不算同一种用户？一次租赁要存几份车况检查？保险、发票、评论应该独立成表还是跟着合同走？被举报三次的公告由谁保证下架？ 这是 UTC NF18 的课程项目。我们最终得到 18 张表：1 张用户母表、3 张用户子表、1 张司机表、1 张车辆表、1 张公告表、1 张合同表、2 张车况检查/发票表、1 张评论表，以及保险、国家、选项、时段和 3 张多对多关联表。下面按设计顺序拆一遍。 先处理“人”的继承 平台上有三类主体：车主、个人租客、企业。它们共享登录名、密码、账号状态，但属性不同： 车主有电话、邮箱、姓名、年龄； 租客还多一个驾照和有效期； 企业有地址、城市、邮编，下面还挂多个司机。 最直接的写法是一张 Utilisateur 表，把所有字段都放进去，再用可空列区分类型。那样查询简单，但会出现大量 NULL，而且数据库无法阻止“企业填了驾照”或“个人填了邮编”这种组合。 我们采用母表 + 子表的继承建模： CREATE TABLE Utilisateur ( pseudo VARCHAR(255) PRIMARY KEY, mot_de_passe VARCHAR(255) NOT NULL, type VARCHAR(255) NOT NULL, actif BOOLEAN, CHECK (type = 'proprietaire' OR type = 'locataire' OR type = 'entreprise') ); CREATE TABLE Proprietaire ( pseudo VARCHAR(255) PRIMARY KEY, telephone VARCHAR(10) CHECK (telephone LIKE '__________') NOT NULL, age INT CHECK (age >= 18) NOT NULL, -- ... FOREIGN KEY (pseudo) REFERENCES Utilisateur(pseudo) ); 子表的主键同时是外键，保证一个账号只能有一种身份。企业司机 Conducteur 则单独一张表，通过 entreprise 外键挂在企业下，因为司机不是平台账号，不需要登录。
