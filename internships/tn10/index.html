工地整改项跟踪与自动定位辅助

巴黎拉德芳斯高层办公楼改造 · ART X BAT · TN10 毕业实习

时间2025.09 - 2026.02 我的角色工程协调实习生（MOEX / OPC） 机构ART X BAT

代码仓库 ↗ 企业项目展示 ↗ 学术档案 →

项目背景

这是我在 ART X BAT 完成的 TN10 毕业实习。岗位方向是 MOEX / OPC——施工阶段的业主代表、施工组织、协调与调度。

实习期间跟进三个类型很不一样的项目：一个新建项目、一个高密度城区的改造项目，以及巴黎拉德芳斯一栋 IGH 高层办公楼的办公层改造（34–39 层，Tour A/B）。主要案例是最后这个高层改造项目。

现场约束很具体：

  • 门禁、访客与授权管理严格；
  • 卸货平台、运输时段和堆放区受限；
  • 多专业交叉作业，界面多；
  • 办公空间高度重复，吊顶龙骨和技术设备呈规律排布；
  • 工期紧，OPR（竣工验收准备）阶段整改项集中爆发。

在这种环境里，MOEX/OPC 的工作不是“记录进度”，而是把现场信息变成可执行的动作：定位、描述、分派、跟踪、验收。

我的工作

现场跟踪

  • 参加例会、记录并澄清技术问题；
  • 按分包核对现场人数，与计划进度对照；
  • 现场巡查、拍照、量测；
  • 跟踪门禁、徽章、授权和技术区域进入；
  • 协调卸货平台、运输、堆放、垃圾箱和现场交通；
  • 按楼层和区域更新进度表；
  • 撰写澄清、催办和留痕邮件。

质量与整改项

  • 按分包识别、汇总整改项；
  • 在 IDCapture 中结构化录入：位置、专业包、企业、描述、期限、照片；
  • 维护状态：待整改、企业已整改、MOE 已验收、有争议、拒绝；
  • 用筛选和统计准备催办清单；
  • 参加 OPR 巡查，发布整合版整改清单；
  • 设置异议表单，形成甲乙双方可追溯的处理流程。

工具落地

  • 梳理参与单位和分包，确定账号清单；
  • 核对用户表、角色和权限；
  • 准备按区域切分、清理后的 PDF 图纸；
  • 设计企业 / MOE / MOA 三级校验流程；
  • 配置“施工跟踪 / OPR / 验收”三个 session；
  • 与软件供应商协调配置；
  • 向施工单位介绍工具、分享教程并组织培训。

问题：失去定位的整改项会失效

一条可执行的整改项至少要回答五个问题：

  1. 在哪里：楼层、区域、图纸、参照点；
  2. 是什么：足够明确的技术描述；
  3. 谁负责：专业分包与施工单位；
  4. 何时完成：期限或截止日期；
  5. 证据：照片、状态历史、验收记录。

OPR 阶段整改项数量会快速上升。在重复性办公空间里，同类问题可能在不同区域出现几十次。为了减少录入量，常见做法是创建一条 “通用整改项”（réserve générale），把多个同类问题合并。

纸面上看很高效，现场却会出问题：这条记录失去了精确位置。施工单位可能只处理了一部分，遗漏另一部分；MOE 无法确认最初到底涉及多少个点，也无法判断是否全部闭合。

结果是：录入更省事，复核、催办和沟通更费事，遗漏、重复和未处理的风险上升。

OpenCV 原型

目标不是替代人工，而是验证一张现场照片能否转化为可用的定位信息。我做了两条流水线。

案例 A：缺少喷淋装饰圈

测试图上有一个人工红圈。处理步骤：

  1. BGR 转 HSV；
  2. 提取红色在 0° 和 180° 附近的两段色域；
  3. 合并两个掩膜；
  4. 做闭运算和开运算；
  5. 提取外轮廓，过滤面积过小的轮廓；
  6. 转成外接矩形。

这条链路在视觉信号足够强时定位稳定，但它检测的是人工标注，不是装饰圈缺失本身。

案例 B：吊顶检修口未复位

这个场景更接近真实情况，不依赖人工标注：

  1. 灰度化、高斯模糊；
  2. 用较宽的矩形核做 blackhat，增强深色接缝；
  3. Canny 提取边缘；
  4. HoughLinesP 提取水平/垂直线段；
  5. 合并邻近位置，重建吊顶网格；
  6. 按网格切分单元，计算均值、标准差和 Laplacian 纹理能量；
  7. 选出“异常单元”；
  8. 在异常单元中，用 blackhat、Otsu 阈值、形态学和面积/长宽比/局部对比度筛选深色细长开口。

这条流水线能产生候选区域，但检测结果容易碎片化，一个开口可能对应多个矩形。施工现场的视觉变化太大，固定规则不够稳定；“整改项”本质上是工程和合同概念，不只是一个暗色区域。

结果与边界

  • 辅助定位有价值：照片可以被转成掩膜、轮廓、候选框、网格单元，这是自动预填整改项的第一步。
  • 单一检测结果不够：要真正落地，需要有代表性的标注数据集、按分包建立的缺陷类型体系、独立验证集和验收指标。
  • 合理的自动化是辅助：给出候选区域、预填整改单，最终由 MOE 确认。
  • 实习期间没有完成监督学习训练，原因是时间和标注数据不足；报告里把它定位为展望，而不是已完成的成果。
