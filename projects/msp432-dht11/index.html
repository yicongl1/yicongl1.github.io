MSP432 + DHT11：手写单总线驱动

上海大学 · 嵌入式系统设计原理与方法（2021 秋）

不依赖传感器库，用 GPIO 与 Timer_A 读出 DHT11 的 40 位数据：18 ms 起始信号、40 µs 采样点、8 位校验和；代码拆成可复用驱动与 UART 示例，并保留原始单文件版本。

2021.09 – 2022.01 C · MSP432 · DriverLib · UART 嵌入式系统设计原理与方法（SHU-23286056） →

为什么手写

DHT11 是最常见的温湿度传感器之一，但它的单总线协议没有标准外设支持：没有 SPI、没有 I²C，只有一根数据线，靠高低电平的宽度传 40 位数据。课程要求用 MSP432P401R + DriverLib 自己实现，不允许直接调用现成传感器库。

这反而适合入门：GPIO 读写、Timer 延时、中断、UART 输出，一个项目里全都用上了。

接线

DHT11 的供电范围是 3.0–5.5 V，3.3 V 与 MSP432 的逻辑电平一致，不需要电平转换。数据线是开漏结构，没有上拉时读到的永远是高电平或浮空，这是最常见的“读不到数据”原因。

时序

一次读取分三段：

  1. 起始：MCU 把数据线拉低至少 18 ms，然后释放；
  2. 响应：传感器拉低约 80 µs，再拉高约 80 µs；
  3. 40 位数据：每一位先有约 50 µs 低电平，然后高电平的宽度决定 0 或 1。

40 µs 这个采样点是整个驱动的核心。太早，0 和 1 都是高；太晚，0 已经回落，1 也可能结束。40 µs 留出了足够的容差。

代码结构

  • dht11.c：起始信号、响应检测、read_byte() 逐位解码、校验和；
  • dht11.h：dht11_init()、dht11_read()、dht11_delay_ms()；
  • main.c：24 MHz DCO、UART A0 115200、每 2 秒读一次并打印 TxxC RHxx%。

延时用 Timer_A 实现：delay_us(n) 把 CCR0 设为 24×n，启动计数，中断里只置一个标志。这样不依赖循环空转，改主频时只需要改一个常数。

read_byte() 的关键循环是：

while (!MAP_GPIO_getInputPinValue(DHT11_PORT, DHT11_PIN) && guard++ < 1000) {}
delay_us(40);
value <<= 1;
if (MAP_GPIO_getInputPinValue(DHT11_PORT, DHT11_PIN)) value |= 1;

第一个循环等 50 µs 低电平结束，延时 40 µs 后采样，第二个循环等这一位的高电平结束。guard 防止传感器掉线时死等。

原始代码里的几个坑

课程版本是单文件，能跑，但有几处不该留：

  • time_count 没有 volatile，中断里改、主循环里读，编译器优化后可能永远等不到；
  • flag 没有初始化，校验失败时返回的是随机值；
  • delay_us 和 delay_ms 重复配置 Timer，delay_ms 又逐毫秒调用 delay_us，精度和开销都不好；
  • 主循环没有失败处理，读不到数据时串口什么也不输出。

拆分后的版本修了这些：volatile、初始化为 0、失败返回 -1、main 里打印失败信息。原始文件保留在 legacy/，方便对照。

结果与限制

在 MSP432P401R LaunchPad + DHT11 上，串口能稳定输出温湿度，LED 每次成功读取翻转一次。限制也很明确：

  • DHT11 分辨率只有 1 °C / 1 %RH，两次读取至少间隔 1 秒；
  • 读取期间阻塞约 20 ms，没有用 DMA 或输入捕获；
  • 只有 8 位校验和，没有 CRC；
  • 长线、缺上拉、电源不稳都会导致校验失败。

如果继续做，我会把解码改成输入捕获 + DMA，让 CPU 在 40 位传输期间做别的事；但这已经超出课程作业的范围。

代码与接线说明在仓库里；实现细节见这篇文章。
