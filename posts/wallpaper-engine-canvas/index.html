把一张壁纸引擎作品搬进网页：拆包、音频与 canvas 动效

  • Canvas
  • Web Audio
  • Wallpaper Engine
  • 性能优化

字体

字号

100%

Wallpaper Engine 上有几张很安静的壁纸：一张雨夜的油画，一张海面上的油画。静止看只是画，动起来靠的是几层很轻的东西——雨丝、水波、颗粒、偶尔一道远处的闪电。

想把它们搬进网页。不是放一段循环视频，而是用 canvas 把动效重新画出来：可以自适应屏幕、能跟着滚轮和鼠标呼吸、手机上也不至于烧电池。这篇文章记录拆包、取音频和复刻动效的整个过程。

一、拆包：.pkg 里有什么

Wallpaper Engine 的工程被打包成 scene.pkg，本质是一个简单的容器：

PKGV0022 | 文件数 | [名字长度 | 名字 | 偏移 | 大小] × N | 数据区

用 RePKG 能解出大部分内容，但遇到 PKGV0022 时它直接返回空。所以写了个几十行的解析器：读 magic、读数量、按表逐个取名字和区间，然后把数据区切成独立文件。

里面主要是三类东西：

  • .tex 纹理（需要再解一次才还原成 png）；
  • .json 场景描述（每个图层的位置、缩放、动效参数）；
  • 音频（音乐、环境声）。

纹理解码交给 RePKG，音频直接就是 mp3/ogg——这部分反而最好处理。

二、图片不是重点，动效才是

把原图铺满屏幕很简单：background-size: cover 加一个位置偏置。真正决定「像不像」的是叠加在上面的几层。

先看那张海面。壁纸里的水面一直在缓慢地扭曲，边缘有很轻的色散，整体颗粒感很重，画面还在轻微抖动。拆成四件事之后，每一件都不难：

1. 水波折射

把画面按横条切开，每一条按正弦波左右错位，再重新拼回去：

for (let i = 0; i < strips; i++) {
  const y = i * h / strips;
  const off = Math.sin(y * 0.0052 + t * 0.9) * 6.4
            + Math.sin(y * 0.019 - t * 1.55) * 2.6;
  ctx.drawImage(buffer, 0, sy, bw, sh, off, y, w, sh);
}

横条不用很细，30 条就够——相邻条之间的位移差不到 1px，接缝看不出来。

2. 色散

把同一帧拆成红、绿、蓝三个缓冲（先用纯色填充、再用 multiply 叠上原图），然后三张各错开 3–5px 用 lighter 加回去。亮部边缘会自然浮出红蓝色边，暗部几乎没有——这正是真实镜头的样子。

3. 颗粒

噪点不能用一张图平移：图有边界，动起来就会看见边缘。正确做法是生成一张可平铺的噪点，用 createPattern 铺满整屏，每帧只随机平移几像素——

ctx.globalCompositeOperation = "overlay";
ctx.globalAlpha = 0.38;
ctx.translate(gx, gy);
ctx.fillStyle = grainPattern;   // repeat，没有边界
ctx.fillRect(-gx, -gy, w, h);

4. 抖动

每 70–130ms 给整幅画面一个随机的 1–3px 位移。频率太高像故障，太低像卡顿，这个区间刚好是「呼吸」。

三、雨、水滴和远处的闪电

另一张是雨夜。它的层次更多：

  • 雨：canvas 线段，长度 8–24px，带一点风向偏移，落到屏幕外就回收；
  • 光晕：不用 canvas，CSS 径向渐变 + blur() + mix-blend-mode: screen，比每帧画渐变便宜得多；
  • 闪电：只在远处出现，沿一条带分叉的折线逐帧生长，而不是整条突然出现。生长 0.6 秒、闪两下、淡出，全程不到 2 秒；
  • 湿玻璃：屏幕上有几颗水珠，出现后顺着往下滑。

水珠这一段改了三轮才像样：

第一版是圆形加一条直线尾迹，一眼假。问题不在形状，而在行为和形状对不上——珠子在左右摆，轮廓却纹丝不动。

第二版给每颗水珠生成自己的轮廓：9 个控制点，叠两个谐波扰动半径，再用二次贝塞尔连成闭合曲线。每颗都不一样，也不再是标准泪滴。

第三版才是关键：

// 速度决定基础拉伸，加速度再叠加：加速时拉长、顿住时回缩
const k = 1 + Math.min(0.28, v * 0.016)
            + clamp(acc * 0.012, -0.2, 0.24);

acc 是每帧速度差再平滑一次的结果。拉长时横向收窄 20%，上沿比下沿拉得多——像被玻璃拖住的那一头。这样它才像水，而不是一个会移动的图标。

内部还做了一次真实折射：把原图放大 1.5 倍、模糊 0.6px，裁剪进水珠轮廓里。落在亮部的水珠会把亮部放大，落在暗处的就是一颗偏暗的珠子——比涂一层发光渐变真实得多。

四、音频

壁纸包的音频是现成的，但直接塞进来有两个问题：体积和循环。

  • 音乐用 64kbps 单声道就够（本来就是氛围声），雨声做一条 20 秒的无缝循环；
  • 用 base64 内嵌，省掉额外请求，也避免路径问题——代价是 HTML 变大，所以只放必要的几段；
  • 用 Web Audio 的 volume 斜坡做淡入淡出，切场景时不会「啪」一下。

浏览器的自动播放策略仍然会拦第一次：先 play() 一次试试，失败就挂一个一次性的 pointerdown/keydown 监听，用户第一次交互时接上。

五、几个反复踩的坑

平铺图层移动会露边。 颗粒层如果用一张图片上下平移，超出元素范围的地方就会露出底下的原图。改成整屏 pattern，或者让元素比视口大出最大位移量。

尾迹永远干不了。 早期把水痕画在一张常驻画布上，用 destination-out 每帧淡一点。低透明度那部分衰减越来越慢，最后屏幕上挂着一层永远擦不掉的灰。改成「只保留最近 1 秒的轨迹点，每帧重画」——水珠消失的那一帧，痕迹一起消失。

性能要提前分层。 三张 canvas 叠在一起，桌面端 30fps 没问题，手机就会烫。现在的策略是：

const motionOK = innerWidth >= 701 &&
  !matchMedia("(prefers-reduced-motion: reduce)").matches;

不满足就只显示原图，不做逐帧合成。动效是锦上添花，不该让页面变卡。

六、这套做法能带走什么

把壁纸搬进网页，真正的成本不在「画得像」，而在「知道哪些东西该由谁来画」：

  • 静态的交给 CSS（背景、光晕、渐变）；
  • 需要逐像素的交给 canvas（雨、水珠、闪电、扭曲）；
  • 需要长期存在的状态交给 JS（场景、音频、偏好）。

想清楚这条分工，同一套方法可以复刻任何一张壁纸：拆包拿到素材，拆层还原动效，再用设备能力决定「哪些层值得开」。剩下的就是耐心——比如让一颗水珠的轮廓跟着加速度呼吸，这件事没有捷径，只能一遍遍看、一遍遍改。

这套动效后来用在了这个网站上，站点本身记录在个人网站项目页里。
