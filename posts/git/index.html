Git 使用学习

本文参考资料

Git 概述

Linus 团队开发的分布式版本控制工具。每台电脑都有完整的版本库，另有一个共享版本库，因此不容易因为单点故障而宕机。

优势：备份、代码还原、协同开发、追溯问题代码的编写人和编写时间、无需中心服务器。

下载地址：https://git-scm.com/download

  • Git GUI：Git 图形界面工具
  • Git Bash：Git 命令行工具

Git 基本配置

  1. 右键打开 Git Bash
  2. 设置用户信息
git config --global user.name "Solal"
git config --global user.email "solal2600@gmail.com"
  1. 查看用户信息
git config --global user.name
git config --global user.email
  1. 设置指令别名
# 创建 bashrc 文件
touch ~/.bashrc

# 输出 git 提交日志
alias git-log='git log --pretty=oneline --all --graph --abbrev-commit'

# 输出当前目录所有文件及基本信息
alias ll='ls -al'

# 运行 bashrc 文件
source ~/.bashrc
  1. 解决 Git Bash 乱码
# 在 Git Bash 中执行
git config --global core.quotepath false

# 在 ${git_home}/etc/bash.bashrc 文件最后加入下面两行
export LANG="zh_CN.UTF-8"
export LC_ALL="zh_CN.UTF-8"

Git 基本工作流程

git init（初始化）

初始化当前目录为一个本地 Git 仓库。完成后当前目录下会多一个 .git 隐藏文件夹。

git add（添加）

将代码从工作区（workspace）提交到暂存区（index）。

git add .

git add . 会添加所有文件、文件夹和子文件夹，包括 .gitignore 和以点开头的其他内容。写在 .gitignore 里的文件名会被忽略。

git commit（提交）

将代码从暂存区提交到本地仓库，本地仓库保存各个历史版本。

git commit -m "注释内容"

git status（查看修改状态）

  • untracked：未跟踪，新创建的文件与 Git 仓库无关联
  • unstaged：未暂存，已有文件被修改
  • staged：已暂存

git log（查看提交日志）

  • --all：显示所有分支
  • --pretty=oneline：将提交信息显示为一行
  • --abbrev-commit：让 commit ID 更简短
  • --graph：以图的形式显示
  • --decorate：新版默认开启
git log --pretty=oneline --all --graph --abbrev-commit

git reflog 可以看到已经删除的提交日志。

git reset（版本回退）

git reset --hard commitID

commitID 可以用 git log 查看。

远程操作

  • clone（克隆）：从远程仓库把代码克隆到本地
  • fetch（抓取）：从远程库抓取到本地仓库，不进行合并，一般用得较少
  • pull（拉取）：从远程库拉取到本地库并自动合并，相当于 fetch + merge
  • push（推送）：把本地修改推送到远程仓库

分支

git branch（查看分支）

git branch (branchname)      # 创建分支
git branch -d (branchname)   # 删除分支（有检查）
git branch -D (branchname)   # 强制删除

git checkout（检出）

从本地仓库检出一个分支并切换过去。

git checkout -b (branchname)   # 创建并切换

git merge（合并）

git merge dev01   # 将 dev01 分支合并到当前分支

如果远程仓库初始化时带了 README，GitHub 会自动生成 main 分支。要和本地历史合并，可以执行：

git merge master --allow-unrelated-histories

解决冲突

  1. 出现 CONFLICT 提示，处理提示中冲突的文件
  2. git add
  3. git commit

常见分支

  • master（生产分支）：主分支，产品交付的版本
  • develop（开发分支）：用于合并同一产品的不同任务
  • hotfix：用于 bug 修复，修完合并回 master 和 develop

远程仓库

常见托管服务

  1. GitHub（https://github.com）：面向开源及私有软件项目的托管平台，只支持 Git 作为版本库格式
  2. Gitee 码云（https://gitee.com/）：国内代码托管平台，服务器在国内，速度通常比 GitHub 快
  3. GitLab（https://about.gitlab.com/）：开源仓库管理系统，常用于企业、学校内部搭建 Git 私服

配置 SSH 公钥

ssh-keygen -t rsa              # 终端输入，然后不断回车
cat ~/.ssh/id_rsa.pub          # 复制并粘贴到 GitHub 设置里
ssh -T git@github.com          # 验证是否配置成功

git remote

git remote                     # 查看远程仓库
git remote -vv                 # 查看远端服务器 URL
git remote add <远端名称> <仓库路径>
  • 远端名称默认是 origin，取决于远端服务器配置
  • 仓库路径从远端服务器获取 URL

git push

git push [-f] [--set-upstream] <远端名称> <本地分支名>:<远端分支名>
  • git push origin master:master：把本地 master 推送到 origin 的 master；名字相同时可简写为 git push origin master
  • -f：强制覆盖
  • --set-upstream：推送时关联本地和远端分支，关联后可以直接 git push
