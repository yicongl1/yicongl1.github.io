用协程刷怪、用状态机巡逻：2D 射击的敌人循环

    项目代码：https://github.com/yicongl1/Unity-Portfolio

    飞龙射击是我做的第一个完整的 2D 竖版射击：玩家移动、连发、随机刷怪、受击反馈、Boss 巡逻。它不复杂，但把几个最常用的 Unity 模式都用了一遍。这篇拆开讲。

    刷怪：一个不会结束的协程

    敌人不是一次性生成的，而是按随机间隔持续出现：

    IEnumerator Create()
{
    while (true)
    {
        float t = Random.Range(minTime, maxTime);
        yield return new WaitForSeconds(t);

        int i = Random.Range(0, monsters.Count);
        Vector3 pos = new Vector3(Random.Range(-2.3f, 2.3f), transform.position.y, 0);
        Instantiate(monsters[i], pos, Quaternion.identity);
    }
}

    用协程而不是在 Update 里累加计时器，好处是“等待”写在代码的顺序里，读起来就是时间线：等一会儿 → 选怪 → 选位置 → 生成 → 再来一次。

    代价是协程跟着 MonoBehaviour 的生命周期走：脚本禁用或物体销毁，协程就停了。如果刷怪器挂在会被销毁的对象上，“突然不刷怪了”通常就是这个原因。

    连发：冷却时间而不是协程

    玩家的射击用的是时间戳：

    public void Fire()
{
    if (Time.time < lastFireTime + fireCD) return;

    Vector3 pos = transform.position + new Vector3(0, 0.8f, 0);
    Transform bullet = Instantiate(prefabBullet, pos, Quaternion.identity);
    lastFireTime = Time.time;
}

    按住 J 时，Update 每帧都会调用 Fire()，但只有距离上次发射超过 fireCD 才真正生成子弹。这比“协程里循环生成”更简单，也不会因为协程被中断而卡住射击。

    受击反馈：颜色 + 时间戳

    敌人被打中时闪红 0.1 s：

    public void OnTriggerEnter2D(Collider2D collision)
{
    SetColor(Color.red);
    changeColorTime = Time.time + hitTime;

    hp -= 1;
    if (hp <= 0)
    {
        Destroy(gameObject);
        Instantiate(prefabBoom, transform.position, Quaternion.identity);
    }
}

    Update 里再把颜色恢复：

    if (Time.time >= changeColorTime) SetColor(Color.white);

    这里同样没有用协程，而是一个“到期时间”。原因是受击可能连续发生：如果用协程，每次受击都要停掉上一个、再开一个新的，管理起来更麻烦；时间戳天然支持“覆盖上一次”。

    Boss：一个最小的状态机

    Boss 只有两个状态：先向下移动到指定高度，然后在左右边界之间往返。

    enum State { Down, LeftRight }

switch (state)
{
    case State.Down:
        pos = transform.position + Vector3.down * speed * Time.deltaTime;
        if (pos.y >= minY) transform.position = pos;
        else state = State.LeftRight;
        break;

    case State.LeftRight:
        if (transform.position.x <= minX) speed = -Mathf.Abs(speed);
        else if (transform.position.x > maxX) speed = Mathf.Abs(speed);
        transform.position += Vector3.left * speed * Time.deltaTime;
        break;
}

    用 enum + switch 而不是一串 if，好处是状态一目了然，新增状态时也不会互相干扰。这里还有个容易忽略的点：用 speed 的符号表示方向，边界处翻转符号即可，不需要额外的方向变量。

    摄像机：按屏幕比例算正交尺寸

    竖版 2D 游戏在不同手机比例下会被裁掉两侧。我用一个很短的脚本按屏幕比例调整正交摄像机：

    float curRatio = (float)Screen.width / Screen.height;
float size = (ratio1 * size1) / curRatio;
cam.orthographicSize = size;

    它的含义是：保持可视宽度不变，让高度随屏幕比例变化。竖屏手机越“长”，orthographicSize 越大，看到的世界越多；横屏时则相反。注释里记了两组实测值（3:4 → 3.75，9:16 → 5），方便以后直接反推。

    如果重做

    • 对象池：子弹和敌人都是高频 Instantiate / Destroy，可以换成池，减少 GC。
    • 配置化：刷怪范围、间隔、Boss 血量现在都是 public 字段，散在 Inspector 里；重做会用 ScriptableObject 收拢。
    • 状态机能再抽象一点：Boss 只有两个状态还好，状态一多就需要统一的 Enter/Update/Exit 接口。
