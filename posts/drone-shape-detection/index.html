用轮廓几何认靶环：一个无量纲判据就够

    项目仓库：https://github.com/yicongl1/Drone-Delivery-2022

    赛题里 A 区是一个 500 mm 的靶环，B、C 区印着不同图案。飞机只有一台 Jetson Nano 和一架下视相机，要在三米左右的高度把靶心找出来，再把落点偏差换算成米发给飞控。

    我们最后没有用模板匹配，也没训练任何模型，判据只有一个数：周长的平方除以面积。

    为什么是这个判据

    对正圆，周长 C 与面积 S 满足 C² = 4πS，所以 C²/(4S) 恒等于 π；对正方形，C²/S 恒等于 16。这两个数都无量纲——与大小无关、与旋转无关、与相机距离无关。

    这意味着不用为每种图案准备模板，不用管飞机飞多高，阈值也只有一个容差，而且物理意义清楚。

    代码里就是这样一行：

    auto area = cv::contourArea(contours[idx]);
auto circumference = cv::arcLength(contours[idx], true);
if (area > 512 &&
    fabs(circumference * circumference / (4 * area) - M_PI) < 0.4) {
    // 这是一个圆
}

    靶心怎么找：取半径最小的那个圆

    靶环是多圈同心圆。判据会把每一圈都筛出来，所以还需要一步“选哪个”：用 r = 2S/C 反推每个圆的等效半径，取半径最小的那一个。

    这一手很关键——靶环最内圈就是靶心，半径最小，天然不会有歧义。不需要知道靶环有几圈，也不需要知道它有多大。

    auto radius = 2 * area / circumference;   // 等效半径
if (radius < min_radius) {
    cv::Moments M = cv::moments(contours[idx]);
    min_radius_center = { M.m10 / M.m00, M.m01 / M.m00 };  // 轮廓矩求质心
    min_radius = radius;
}

    质心用轮廓矩而不是外接框中心，是因为稍微斜视一点，外接框中心就会偏，而矩心几乎不动。

    前处理比判据重要

    轮廓法的成败几乎全在前处理：

    1. 双边滤波 bilateralFilter(img, out, 3, 1024, 1024)——去噪但保边。用高斯滤波会把圆的边界糊掉，Canny 之后就闭合不起来了；
    2. Canny（24, 144）：高低阈值比约 1:6，是试出来的；
    3. 9 × 9 闭运算：把断开的边缘接上。靶环在低对比度处边缘经常断；
    4. 3 × 3 开运算：去掉地面反光形成的小亮点；
    5. findContours + area > 512：先把明显不是靶环的碎轮廓扔掉。

    顺序不能反：先闭后开，是“先该连的连上，再该丢的丢掉”；反过来会把断口当噪点清掉。

    像素偏差怎么变成米

    拿到质心后，偏差是 480 − cx 和 270 − cy（相对 960 × 540 的图像中心），再用针孔模型换算：

    double a = error_y * sensor_x * pos_drone[2] / (x_size * fx);
double b = error_x * sensor_y * pos_drone[2] / (y_size * fy);

    其中 sensor_x = 3.2、sensor_y = 2.4(mm)，fx = 4.476、fy = 5.96（标定焦距），pos_drone[2] 是当前高度。

    两个细节：

    • 高度直接乘进结果：飞得越高，同样的像素偏差对应的实际距离越大。高度估错 20%，落点就偏 20%；
    • 行列是交叉用的：x 方向的实际偏差由 y 方向的像素误差算，反之亦然。这是相机安装方向决定的，不是笔误——第一次读这段代码的人十有八九会以为写反了。

    三个没做对的地方

    只有单帧判定。 画面里出现一个恰好符合判据的干扰轮廓（地上的圆形贴纸、光斑），偏差立刻被发出去，没有任何平滑或确认。正确做法至少有两条：多帧一致性投票，或者对偏差序列做一次低通。

    用 （0, 0） 当“没检测到”的哨兵值。 if((cx != 0) && (cy != 0)) 才发布。数学上没问题，但检测真的落在图像中心附近时，代码分不清“没检测到”和“正对着目标”——而“正对着目标”恰恰是最该发布的时候。

    焦距是死值。 fx、fy、传感器尺寸都写死在源文件里，是按当时那台 CSI 相机标定的，换镜头就得重标。

    如果重来

    • 判据保留，加一层时间维度。 结构不变，只在后面接一个 5 帧滑动窗：少于 3 帧命中就丢弃，命中则取中位数。成本几乎为零，却能把“偶发误检”这个最大风险直接砍掉；
    • 标定参数外置。 内参、传感器尺寸、图像中心统一进 yaml，和 launch 一起加载；
    • 加一条“看不见就悬停”的兜底。 现在检测失败时飞机仍按盲飞落点投放；改成“连续 N 帧无目标则悬停等待”，就能把一次误投变成一次重试。

    回头看，这套方法在 2022 年那台 Nano 上是合适的：轻、无需训练、调试直观。它的问题不在判据本身，而在判据之外没有第二道防线——单个轮廓就能改变飞机的动作，这是工程上最不该有的结构。
