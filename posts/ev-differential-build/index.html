两块 TT 电机、一块 L298N：把电子差速装进 Arduino 小车

    项目仓库：https://github.com/yicongl1/EV-Electronic-Differential

    上一篇算的是“内外轮应该差多少”，这一篇讲“怎么让一台几十块钱的小车真的差起来”。硬件不复杂：Arduino Uno、L298N、两个 TT 电机、一个 MG995 舵机、一个红外接收器、两节 18650。真正花时间的是接线、供电和几个旧版库的坑。

    硬件与接线

    功能Arduino 引脚
    左电机 A / B（L298N IN1 / IN2）5 / 6
    右电机 A / B（L298N IN3 / IN4）9 / 10
    MG995 舵机信号11
    HX1838 红外接收 OUT3

    电源方面，两节 18650 接 L298N 的 12V / GND，Arduino 与 L298N 共地。舵机建议单独 5V 供电——MG995 堵转电流很大，和电机共用一路时，电机一启动舵机就抖，严重时 Arduino 会复位。

    L298N 到底在做什么

    L298N 是双 H 桥。每一路有 IN1/IN2 两个方向引脚和一个使能端：

    • IN1 = 高，IN2 = 低：正转；
    • IN1 = 低，IN2 = 高：反转；
    • 两路都低：滑行停止；
    • 使能端（或直接对 IN 引脚做 PWM）决定平均电压，也就是转速。

    代码里没有用独立的使能引脚，而是直接对 IN1/IN2 做 analogWrite：

    void forward() {
  analogWrite(leftA_PIN, 180);
  analogWrite(leftB_PIN, 0);
  analogWrite(righA_PIN, 180);
  analogWrite(righB_PIN, 0);
  myservo.write(90);
}

    前进用 180 而不是 255，是留一点余量：满占空比时电机电流最大，电池电压一掉，左右轮的差异反而更明显；留 30% 的余量，转向时内侧降到 120 也还有调节空间。

    转弯函数只改内侧：

    void turnleft() {
  analogWrite(leftA_PIN, 120);   // 内侧慢
  analogWrite(leftB_PIN, 0);
  analogWrite(righA_PIN, 180);   // 外侧快
  analogWrite(righB_PIN, 0);
  myservo.write(45);
}

    这就是上一篇那个 120/180 的开环差速：没有测速，纯粹按几何比例给占空比。

    红外遥控的旧 API

    红外接收器用 HX1838，接 D3。代码用的是 IRremote 2.x：

    #include <IRremote.h>

IRrecv irrecv(3);
decode_results results;

void loop() {
  if (irrecv.decode(&results)) {
    Serial.println(results.value, DEC);
    irrecv.resume();
  }
}

    这套 IRrecv / decode_results / resume() 在 IRremote 3.x 里已经不存在了。直接 pip/库管理器装最新版会编译失败，必须锁定 2.x。键值也不同：代码里判断的是 16718055、16730805 这些十进制数，换一个遥控器就要重新记录。

    另一个细节是消抖。红外接收在按住按键时会连续输出，代码里用 delay(500) 让一次按键只执行一个动作，再用 results.value == 0x16 加 600 ms 延时处理重复码。这是很粗糙的做法，但在这台小车上够用。

    为什么还要做 pygame 动画

    硬件小车一次只能演示一个动作，而且调试时经常翻车。pygame 动画把“四个轮子的转速”做成可视变量：

    • 每个轮子有 v、a、turn、angle 四个状态；
    • W 加速，A / D 转向，松开按键停车；
    • 轮速映射为三张图片：静止、中速、高速；
    • 转弯时内侧轮速下降，外侧轮速上升，车身角度跟着转。

    四个版本是逐步加上去的：

    • v1.0：四轮 + 速度颜色映射；
    • v1.1：加方向指示；
    • v1.2：加车轮转角；
    • v2.0：加公路背景，车轮随转角旋转。

    它不是车辆动力学仿真，只是一个“把差速关系画出来”的教学动画。update_a 里的加速度、上限和转角都是手调参数，不对应真实物理量。

    神经网络示例的边界

    仓库里还有一个 keras_test.py，用 Boston Housing 数据集做 4 折交叉验证，输出每折 MAE。它的作用是验证回归网络的训练与评估流程，不是用实车数据拟合“差速—转角”关系。README 里写得很清楚：

    • 示例只验证建模流程；
    • 论文里的差速—转角关系属于方案设计；
    • 真要用神经网络，需要先有轮速、转角和车辆状态的实测数据。

    把“示例”和“结果”分开写，是这类课程项目最容易被忽略的诚实。

    还能怎么改

    • 加编码器：TT 电机尾部可以装霍尔编码器，拿到左右轮实际转速，做速度闭环；
    • 给舵机加反馈：电位器或角度传感器，避免“写 45° 就假设前轮转 30°”；
    • 统一参数：把 120/180、45°/90°/135°、轴距、轮距提到一个配置里，换车时不用改代码；
    • 加电流限制：堵转时 L298N 和电机都容易发热，电池也扛不住。

    这台小车完成于 2022 年初，代码保留了原貌。它证明了一件事：电子差速的原理可以用很低的成本跑通；但要把它变成可靠的控制系统，传感器和反馈一个都不能少。
