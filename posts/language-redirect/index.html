静态站的语言跳转：为什么我没用 IP 定位

    站点有中文、英文、法文三个版本。之前的做法是让访客自己点右上角的语言选择器；最近加了一个“首次访问自动跳转”，规则很简单：

    • 浏览器语言是法语 → /fr/
    • 浏览器语言是中文 → 中文首页
    • 其他语言 → /en/

    没有采集 IP，也没有调用任何第三方接口。

    这篇记录为什么这么做，以及静态站做语言跳转时容易踩的坑。

    静态站拿不到 IP

    这是最先要接受的事实。GitHub Pages 这类纯静态托管只负责把文件发出去，不执行服务端代码，所以：

    • 不能在服务器端读 X-Forwarded-For
    • 不能根据国家做 302
    • 不能在 HTML 返回前决定语言

    想在浏览器里按国家跳转，只能调用第三方 IP 地理库：

    const res = await fetch("https://ipwho.is/");
const { country_code } = await res.json();

    这能工作，但代价不小：

    1. 多一次外部请求：首屏要等它返回，慢的时候会先看到中文再跳走。
    2. 隐私问题：IP 属于个人数据。站点在法国，面向欧洲访客时，把每个访客的 IP 发给第三方需要更谨慎地说明处理目的。
    3. 误判：VPN、公司出口 IP、跨境网络都会让“国家”不等于“语言”。
    4. 可用性：免费接口有限流，挂掉时只能回退。

    对个人作品集来说，这些成本换来的精度并不值得。

    浏览器语言是更直接的信号

    访客想要什么语言，浏览器其实已经说了：

    navigator.language        // "fr-FR"
navigator.languages       // ["fr-FR", "fr", "en"]

    它比 IP 更接近“用户能读什么语言”，而不是“用户此刻在哪”。一个法国人在德国出差，浏览器仍然是 fr-FR；一个在法国的英语使用者，浏览器是 en-US。按语言跳转比按国家跳转更符合实际需求。

    最终的判断逻辑：

    const langs = navigator.languages.length
  ? navigator.languages
  : [navigator.language];

const preferred = langs[0].toLowerCase();

if (preferred.startsWith("fr")) {
  location.replace("/fr/");
} else if (!preferred.startsWith("zh")) {
  location.replace("/en/");
}

    中文不跳转，因为中文就在根路径 /。

    只在首页跳，避免循环

    跳转脚本只放在中文首页。原因：

    • 如果每个页面都跑，访客从 /en/ 点回中文页时会被再次弹回英文，形成来回跳。
    • 只在入口页判断一次，之后由访客自己的导航决定。

    同时要防止“跳转目标又被跳转”：

    /        → 根据语言跳到 /fr/ 或 /en/
/en/     → 不再执行跳转
/fr/     → 不再执行跳转

    跳过爬虫

    如果搜索引擎爬虫的 IP/语言被判断成英文，它可能只抓英文版，中文和法文页面就少了索引入口。

    所以脚本里加了 UA 过滤：

    if (/bot|crawl|spider|slurp|bingpreview|facebookexternalhit|twitterbird/i.test(navigator.userAgent)) {
  return;
}

    也跳过 navigator.webdriver，避免自动化测试和无头浏览器被重定向。

    更严谨的做法是用 Vary: Accept-Language 或服务端 302，但静态托管做不到；客户端跳转至少不要干扰爬虫。

    记住用户的手动选择

    自动判断一定会有错的时候。一个中文用户用英文浏览器，第一次被送到 /en/，他点右上角切回中文；如果下次访问又被送回英文，就很烦。

    解决方式是记住手动选择：

    document.addEventListener("click", (event) => {
  const link = event.target.closest("a.languages-item");
  if (!link) return;

  const href = link.getAttribute("href");
  const choice = href.startsWith("/fr") ? "fr"
    : href.startsWith("/en") ? "en"
    : "zh";

  localStorage.setItem("lang-choice", choice);
});

    首页跳转前先检查：

    if (localStorage.getItem("lang-choice")) return;

    这样自动跳转只影响“第一次来、还没表达过偏好”的访客。

    测试

    无头浏览器可以直接指定语言，验证不同分支：

    msedge --headless --lang=fr-FR --accept-lang=fr-FR \
  --dump-dom http://localhost:8080/
    • fr-FR → 法文页
    • en-US → 英文页
    • zh-CN → 中文页不变

    比手动改浏览器设置可靠得多。

    什么时候才值得上 IP

    如果需求真的是“按国家”而不是“按语言”，比如：

    • 某些内容只在特定国家可见
    • 需要按国家显示不同的联系方式或合规声明
    • 语言和国家的对应关系非常明确（例如本地化电商）

    那才值得引入 IP 地理库，并且应该：

    1. 用服务端或边缘函数（Cloudflare Workers、Vercel Edge）读取 IP，而不是浏览器里再发一次请求
    2. 提供明显的语言切换入口，并记住选择
    3. 在隐私政策里说明 IP 的用途
    4. 准备好接口失败时的回退

    对一个三语个人网站来说，浏览器语言已经够用了。

    小结

    静态站做自动跳转，核心不是“怎么拿到地理位置”，而是“用什么信号判断用户需要什么”。

    • IP 回答的是“你在哪”
    • 浏览器语言回答的是“你能读什么”

    对于作品集、博客、文档这类内容，后者通常更准确，也更便宜、更干净。
