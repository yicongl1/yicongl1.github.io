把一整年实测数据喂给 Simulink：日循环、时间序列与能量积分

    项目代码：https://github.com/yicongl1/MPPT-direct

    光伏 MPPT 的仿真不难在建模型，难在数据：一年的实测辐照度和温度，怎么变成 Simulink 能吃的输入？跑完 366 天之后，又怎么把瞬时功率换成 kWh 和效率？这篇记录这条数据管道，以及几个当时踩过的坑。

    数据的形状

    UTC 的 STELLA 平台给的是三个 Excel：辐照度、环境温度、电池温度。每个文件的结构都很“表格化”：

    • 第 1 行是时刻表头，对应一天里的第 0~1439 分钟；
    • 第 1 列是日期，ISO 格式 yyyy-mm-dd；
    • 中间 1440 列，是这一天每分钟的测量值；
    • 一共 366 行，对应 2023-04-01 到 2024-03-31。

    也就是说，一个文件是 366 × 1441 的矩阵，时间被摊平在列方向上。

    第一个坑：Excel 会把第 1 行的时刻（00:00、00:01……）识别成日期，显示成 1899-12-30 之类的怪值。不要试图去“修复”它——反正第 1 行只是表头，读进来直接丢掉。

    读入与时间轴

    MATLAB 里用 readtable 读，然后跳过第 1 行和第 1 列：

    temperatureTable = readtable(fullfile(rawDir, 'CellT.xlsx'));
irradianceTable  = readtable(fullfile(rawDir, 'Irradiation.xlsx'));

numDays = size(temperatureTable, 1) - 1;   % 去掉表头行
numTimes = 24 * 60;                        % 每天 1440 点

temperature = table2array(temperatureTable(2:end, 2:end));
irradiance  = table2array(irradianceTable(2:end, 2:end));

    接下来要造一条绝对时间轴：第 1 天 00:00 到第 366 天 23:59，每分钟一个点。

    timeStamps = NaT(numDays * numTimes, 1);
for i = 1:numDays
    start = (i - 1) * numTimes;
    timeStamps(start + 1 : start + numTimes) = ...
        datetime(dateStrings{i}) + minutes(0:numTimes - 1)';
end

elapsed = seconds(timeStamps - timeStamps(1));
tsTemperature = timeseries(temperature(:), elapsed);
tsIrradiance  = timeseries(irradiance(:),  elapsed);

    注意 temperature(:)：把 366×1440 的矩阵按列优先拉直，正好和逐日递增的时间轴对上。如果顺序反了，仿真不会报错，但所有数据都会错位——这种 bug 比崩溃更难查。

    取一天，重置时间

    Simulink 的 From Workspace 模块吃的是工作区里的 timeseries。整年跑一次不现实，所以按天循环：每次取 1440 个样本，把时间轴重新从 0 开始。

    dayIndex = find(strcmp(dateStrings, requestedDate), 1);
samples = (dayIndex - 1) * numTimes + (1:numTimes);

tsTemperatureDay = getsamples(tsTemperature, samples);
tsIrradianceDay  = getsamples(tsIrradiance,  samples);

tsTemperatureDay.Time = tsTemperatureDay.Time - tsTemperatureDay.Time(1);
tsIrradianceDay.Time  = tsIrradianceDay.Time  - tsIrradianceDay.Time(1);

    时间轴必须从 0 开始，否则每天都要把仿真起点往后推，模型里的初值、控制器状态都会跟着漂。

    注入工作区只需要两行：

    assignin('base', 'ts_temperature', tsTemperatureDay);
assignin('base', 'ts_irradiance',  tsIrradianceDay);

    变量名必须和模型里 From Workspace 的配置一致。这是 Simulink 脚本化最常见的失败点：名字对不上，仿真直接用空数据跑完，结果一片零。

    366 天怎么跑

    逐日 sim，把每天的功率拼起来：

    for i = 1:numDays
    [tsTj, tsGj] = loadDayData(tsTemperature, tsIrradiance, dateStrings, dateStrings{i});
    assignin('base', 'ts_temperature', tsTj);
    assignin('base', 'ts_irradiance',  tsGj);

    dayOut = sim(modelName);
    PO  = [PO;  asVector(dayOut.PO)];
    POA = [POA; asVector(dayOut.POA)];
end

    按当时的机器，一天大约一分钟，366 天就是几个小时。这个量级决定了不能用“跑一次改一个参数”的方式做调参，必须先把单日仿真跑通，再批量跑。

    还有一个细节：sim 返回的可能是 timeseries，也可能是普通数组，取决于模型配置。所以拼接口前统一转成列向量：

    function values = asVector(signal)
    if isa(signal, 'timeseries')
        values = signal.Data(:);
    else
        values = signal(:);
    end
end

    从功率到 kWh

    仿真步长是 2 s，一天有 86400 / 2 = 43200 个采样点。把全年功率按天 reshape，再乘上每个采样代表的时长：

    samplesPerDay = round(86400 / sampleTime);
numDays = numel(power) / samplesPerDay;
reshaped = reshape(power, samplesPerDay, numDays)';

dailyEnergy = sum(reshaped / 1000 * (sampleTime / 3600), 2);
annualEnergy = sum(dailyEnergy);

    /1000 是 W → kW，sampleTime/3600 是秒 → 小时。两件事都不能漏，否则结果会差三个数量级。

    如果采样点数不是一天的整数倍（比如仿真提前结束），代码会把最后一个值重复补齐，并给出 warning。这个处理不优雅，但比静默截断好：至少你知道数据被动过。

    效率的分母

    效率的定义是“发电量 / 入射太阳能”：

    η = E_PV / E_solar

    分母同样用 computeDailyEnergy 算，只是输入换成辐照度（W/m²），步长换成数据的 60 s。这里有两个容易忽略的点：

    1. 年度效率是“和的比”，不是“比的平均”：
    annualEfficiency = sum(dailyEnergy) / sum(dailyIrradiance);

    如果先算每天的 η 再取平均，阴天会被赋予和晴天相同的权重，结果偏高。

    1. 分母接近 0 时不要硬除。夜间和清晨的入射能量很小，任何微小的功率残差都会让日效率炸成很大的正数或负数。仓库里 data/processed/efficiency_data.csv 的前几天就出现了负值——这是直接相除的结果，不是算法坏了，但解读时要先过滤掉低辐照日。

    代码分层

    课程结束后我把脚本重写成了三层：

    src/data/       loadYearData.m, loadDayData.m      读数据、造时间轴
src/           runSimulation.m, runYearSimulation.m 单日 / 全年仿真
src/analysis/  computeDailyEnergy.m, computeEfficiency.m, plotDailyComparison.m
src/runAnalysis.m                                   串起 CSV、效率与图

    好处是每一层都能单独验证：先确认读进来的数据形状对不对，再确认单日功率曲线像不像太阳，最后才看全年统计。全部用 projectRoot() 推导相对路径，仓库复制到哪台机器都能跑。

    代价是没有自动化测试。MATLAB 的测试框架在课程项目里不好落地，所以只能在 README 里写清楚复现步骤，并在“已知限制”里注明：先跑单日，再跑全年。

    复现命令

    cd('MPPT-direct 所在路径');
addpath('src');
setupProject();

[tsT, tsG, dates] = loadYearData();
out = runSimulation('2023-07-01');
runAnalysis(out, 'Irradiance', tsG.Data);

    跑全年把 runSimulation 换成 runYearSimulation，大约需要几个小时。
