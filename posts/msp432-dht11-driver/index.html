手写 DHT11：不用库，在 MSP432 上读 40 位

  • C
  • MSP432
  • 嵌入式
  • DHT11
  • 单总线

字体

字号

100%

嵌入式课上，老师给了一块 MSP432P401R 和一颗 DHT11，要求不用传感器库，自己把温湿度读出来。DHT11 没有 SPI、没有 I²C，只有一根数据线，靠高低电平的宽度传 40 位数据——这反而成了我第一个真正意义上的“时序”练习。

接线

DHT11 三根线：VCC、GND、DATA。DATA 接 MSP432 的 P3.6，并且必须用一个 4.7–10 kΩ 的电阻上拉到 3.3 V。

时序：40 µs 是分界线

一次读取分三段：

  1. MCU 拉低数据线至少 18 ms，然后释放；
  2. 传感器回应约 80 µs 低 + 80 µs 高；
  3. 40 位数据，每位先有约 50 µs 低电平，然后高电平的宽度决定 0 或 1。

40 µs 这个点很关键：太早，0 和 1 都是高；太晚，0 已经回落，1 也可能结束。选在中间，留出的容差最大。

代码

驱动分成三个文件：

  • dht11.c：起始信号、响应检测、read_byte() 逐位解码、校验和；
  • dht11.h：dht11_init()、dht11_read()、dht11_delay_ms()；
  • main.c：24 MHz DCO、UART A0 115200、每 2 秒打印一次 TxxC RHxx%。

延时用 Timer_A 实现，而不是空循环：

static void delay_us(unsigned int us) {
    Timer_A_UpModeConfig cfg = { ... /* period = 24 * us */ };
    g_timer_done = 0;
    MAP_Timer_A_configureUpMode(TIMER_A1_MODULE, &cfg);
    MAP_Interrupt_enableInterrupt(INT_TA1_0);
    MAP_Timer_A_startCounter(TIMER_A1_MODULE, TIMER_A_UP_MODE);
    while (!g_timer_done) {}
}

中断里只做一件事：把 g_timer_done 置 1。这样延时和主频绑定得很清楚，改主频只需要改一个常数。

read_byte() 的逻辑是：等 50 µs 低电平结束 → 延时 40 µs → 读电平 → 等这一位的高电平结束。每一层等待都有一个 guard 计数，防止传感器掉线时死循环。

原始代码里的坑

课程版本是单文件，能跑，但有几处不该留：

  • time_count 没有 volatile，中断里改、主循环里读，开优化后可能永远等不到；
  • flag 没有初始化，校验失败时返回的是随机值；
  • delay_ms 逐毫秒调用 delay_us，每次都重配 Timer；
  • 主循环没有失败分支，读不到数据时串口什么也不输出。

拆分后的版本把这些都修了：volatile、初始化为 0、失败返回 -1、main 里打印错误。原始文件放在 legacy/，方便对照。

限制

DHT11 的分辨率只有 1 °C / 1 %RH，两次读取至少间隔 1 秒；读取期间阻塞约 20 ms；只有 8 位校验和，没有 CRC。长线、缺上拉、电源不稳都会导致校验失败。

如果继续做，我会把解码改成输入捕获 + DMA，让 CPU 在 40 位传输期间做别的事。但这已经超出课程作业的范围了。
