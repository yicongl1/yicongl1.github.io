给简历写一个生成器：从主页数据到 A4 PDF

  • JavaScript
  • Hugo
  • PDF
  • 简历

字体

字号

100%

每次投申请，简历都要改一遍：这个岗位多放两个项目，那个项目砍掉一段经历；中文版、英文版、法文版各改一次。主页上的数据明明是现成的，简历却要手工维护，时间一长两边就对不上。

于是有了 /cv/：一个只给自己用的简历生成器。左边勾选语言和条目，右边实时预览 A4 纸面，点一下直接下载 PDF。这篇文章记录它是怎么搭起来的，以及中间踩到的几个坑。

一、数据从哪来

站点的首页本身是数据驱动的：教育、实习、项目、竞赛、技能、链接分别放在 data/<lang>/sections/*.yaml 里，Toha 主题负责渲染。简历生成器没有另起一套数据，而是在构建时把三种语言的这些 YAML 直接嵌进页面：

{{- $langs := slice "zh-cn" "en" "fr" -}}
{{- $cvData := dict -}}
{{- range $lang := $langs -}}
  {{- $entry := dict -}}
  {{- $d := index site.Data $lang -}}
  {{- $sec := $d.sections -}}
  {{- range $key := slice "about" "education" "experiences" "projects"
        "competitions" "achievements" "skills" "connect" -}}
    {{- $entry = merge $entry (dict $key (index $sec $key | default (dict))) -}}
  {{- end -}}
  {{- $cvData = merge $cvData (dict $lang $entry) -}}
{{- end -}}

这样只有一处真相：主页改了什么，简历里就有什么。三个语言版本也天然一致，不需要各自维护。

二、一个不显眼的坑：script 标签里的 JS 上下文

第一版把所有数据渲染进 <script type="application/json">，结果页面里的 JSON 完全解析不了，打开看是这样一个东西：

"{\"en\":{\"about\":{\"badges\":[...]"

整段 JSON 被多包了一层引号，里面的引号全被转义了。原因不在 jsonify，而在 Go 模板的上下文感知转义：模板引擎看到输出位置在 <script> 标签里，会按 JavaScript 字符串字面量的规则来转义，于是把整段 JSON 当成一个字符串，套上引号。

修复只需要一个过滤器：

<script id="cv-data" type="application/json">{{ $cvData | jsonify | safeJS }}</script>

jsonify 保证输出是合法 JSON，而 JSON 本身就是合法的 JS 字面量；safeJS 告诉模板引擎「这段内容已经是安全的 JS，别再包一层」。这个坑在任何 Hugo 站点里往 <script> 注入 JSON 时都会遇到，值得记一笔。

三、勾选、排序与记忆

左侧面板按板块分组：每个板块可以整组开关、上下移动；组内每个条目也可以单独勾选、排序。状态结构大致是：

state = {
  lang: 'zh-cn',
  contact: true,
  avatar: true,
  style: { size: 'md', font: 'sans', layout: 'single' },
  groups: { 'zh-cn': { projects: { enabled: true, selected: [...], order: [...] } } },
  groupOrder: {}
}

整个对象序列化进 localStorage。数据文件以后新增条目时，旧的选择状态长度对不上，就对该组回退为默认全选——不会因为索引错位丢内容。

四、难点其实是 A4 分页

一开始我把整份简历渲染成一张长图，按 1123px 切片塞进 PDF。问题很快出现：

  • 文字会从行中间被切断；
  • 板块标题可能落在页脚，下面跟着下页的内容；
  • 测量用 offsetHeight 取整，误差累积几像素，最后一行几乎贴到纸边。

最终方案是按块分页：

  1. 把内容拆成「标题块 + 条目块」，每个块不可再拆；
  2. 在隐藏的量纸容器里测量每块的真实高度；
  3. 按页容量装箱，标题块附带上第一条内容一起判断，放不下就整体换页；
  4. 每页独立渲染成一个 794×1123 的 A4 容器。

关键细节都在测量的精度上：

// getBoundingClientRect 保留小数，Math.ceil 保证不会少算
b.h = Math.ceil(b.node.getBoundingClientRect().height);

// 每页底部再留 8px，字体度量有误差也不会把最后一行顶到页脚
var avail = 1123 - 54 - 46 - 8;

还有一个隐蔽的时序问题：Web 字体加载完成前后，行高会变。首页首次渲染发生在字体就绪之前，实测高度就偏小。解决办法是在 document.fonts.ready 之后重排一次：

if (document.fonts && document.fonts.ready) {
  document.fonts.ready.then(function () { renderPreview(); });
}

五、导出：每页一张图，链接单独标注

PDF 用 html2canvas 逐页截图，再用 jsPDF 一页一页写入。截图时要把预览的缩放临时撤掉，否则 html2canvas 会按缩放后的尺寸抓图：

.cv-capturing .cv-scale { transform: none !important; }

为了让文字在高倍缩放或打印时依然锐利，导出用 3 倍像素密度、PNG 编码：

var canvas = await html2canvas(pageEl, {
  scale: 3, backgroundColor: '#ffffff', logging: false
});
pdf.addImage(canvas.toDataURL('image/png'), 'PNG', 0, 0, pw, ph);

页面是位图，超链接本来会丢。但 jsPDF 允许在图片上方叠加链接注释：把每个 <a> 的包围盒换算成 PDF 坐标，再调用 pdf.link() 即可。打印出来看不到注释，电子版却可以点击。考虑到纸质简历没有超链接，条目后面干脆把完整网址直接印出来。

六、排版：字号、字体与边栏

样式选项做了三组：

  • 字号：小 / 中 / 大；
  • 字体：无衬线（Segoe UI + 微软雅黑）/ 衬线（Georgia + 宋体）；
  • 版面：单栏，或把技能、语言能力、链接放进左侧 190px 窄栏。

为了让字号能整体缩放，纸面内所有文字尺寸都改成 em，基准是 --cv-fs：

.cv-sheet { --cv-fs: 12.5px; font-size: var(--cv-fs); }
.cv-sheet.cv-size-sm { --cv-fs: 11.5px; }
.cv-sheet.cv-size-lg { --cv-fs: 13.6px; }

边栏模式不是简单地把页面切成两列：主栏和边栏各自装箱分页，页数取较多的那一边。测量时也必须用真实的栏宽，否则换行位置不同，高度全都对不上——这也是量纸容器要完整镜像页面结构的原因。

纸面固定浅色、不跟随站点深色主题：简历是要打印的，界面可以深色，白纸不能变色。

七、链接与三语

条目链接按生成语言自动本地化，规则和首页模板里的 relLangURL 一致：站内路径没有语言前缀时，英文简历补 /en/、法文补 /fr/。中文平台（Gitee、CSDN、LeetCode 中文站、洛谷）在英法简历里标注 (Chinese) / (Chinois)，读者点开之前就知道内容语言。

八、回顾

这个工具不大，但它把「内容」和「排版」彻底分开了：数据继续在主页维护，简历只是同一份数据的另一种视图。真正花时间的不是界面，而是分页的边界情况——块高度、字体时序、页面留白，都是「看起来差不多」和「打印出来能用」之间的差距。

下一步想做的：给边栏加每组一个开关（比如让教育经历也能进边栏）、自动压缩到两页以内、以及记住每份投递对应的勾选组合。等用出问题再说。

这个工具属于个人网站项目，项目页里有它的整体结构和相关文章。
