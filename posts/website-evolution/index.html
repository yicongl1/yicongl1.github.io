从 Solal2600 到 yicongl1：一个个人网站的两次搭建

  • Hugo
  • 个人网站
  • 改版
  • Toha
  • GitHub Pages

字体

字号

100%

我现在这个站不是第一次做。2022 年 9 月，我用当时的 GitHub 账号 Solal2600 搭过一版 Hugo 博客；2024 年 4 月，账号换成 yicongl1 之后，又从零搭了现在这一版。

两个站用的是同一套工具链——Hugo + GitHub Pages、Markdown 写作、B 站视频嵌入——但它们的定位完全不同：第一版是「记录」，第二版是「作品集」。这篇文章把两次搭建放在一起，看看中间到底改了什么。

第一版：一个按时间排列的博客

第一版用的是 Stack 主题，标题就叫「Personal Website Of Solal」。配置很轻：中文、每页 5 篇、分类是「专业学习 / 写作 / 法国留学 / 读书 / 运动」，标签里是 Git、无人机、机器学习、音乐这些。

从 2022 年 9 月到 2023 年 7 月，那里大概发了十几篇东西：无人机调试、Git 使用、GPU 服务器、法国吉他购买，也有阅读、做饭、赴法准备和生活记录。归档页显示 2022 年 2 篇、2023 年 11 篇。

那一版的好处是几乎没有门槛：新建一个 content/post/*.md，写 Markdown，放一张封面图，推送就发布。B 站视频用一个 shortcode 嵌进去，分类和标签自动生成归档页。对当时的我来说，它更像一本公开的笔记本——学到什么、去了哪里、读了什么，都往里放。

问题也在这里。等到要拿它去找实习、申请学校时，我发现访客看到的是一串按时间排列的随笔：无人机调试的下一篇可能是鸡胸肉的做法，再下一篇是一段很私人的情绪。它能证明「我在写」，但证明不了「我会什么」。

第二版：从博客改成作品集

2024 年 4 月，我换了 GitHub 账号，也决定把站点重做。新站用 Toha 打底，但首页、项目、竞赛、学业档案、简历这些页面都用自己的模板覆盖了。

最大的变化不是主题，而是信息架构：

  • 首页不再是一串文章，而是一份可以滚动的简历：关于 → 技能 → 经历 → 教育 → 项目 → 竞赛 → 链接；
  • 项目和竞赛有详情页，写清楚时间、角色、技术栈、相关文章；
  • 学业档案按学期列出课程、成绩、学分，课程代码是锚点，可以从项目页跳回课程，也可以从课程跳到项目；
  • /cv/ 用同一份数据生成 A4 简历，勾选语言和条目就能导出 PDF。

支撑这些页面的是 data/ 下的 YAML：加一门课、加一个项目、换一张图，都只是改数据，不用碰模板。这是第一版完全没有的东西——第一版的所有信息都埋在文章正文里。

中间做对的几件事

内容是可迁移的。 旧站的文章都是 Markdown，换主题、换仓库、换域名，正文本身不用重写。真正会丢的是 URL：账号从 Solal2600 换成 yicongl1，旧链接就全部失效了。如果以后还会换域名，应该提前想好重定向，或者至少把文章标题和日期保留下来，方便重建索引。

有些文章不适合公开。 旧站里有一部分是私人记录，放在公开博客上并不合适。新站后来做了一个加密区，把「写给自己的」和「给别人看的」分开；公开页面只保留项目、课程和技术复盘。

发布范围要提前设计。 现在源码在一个私有仓库，公开仓库只接收构建产物；publish.ps1 每次重新构建、把产物压成一次提交再强推。这样公开的 GitHub Pages 仓库里不会出现草稿、脚本和加密区的明文，源码历史则完整保留。

也踩过的坑

  • 缓存：自定义的 site.css 文件名不变，浏览器会一直用旧版本；后来用内容哈希做查询参数才解决。
  • 多语言链接：relURL 和 relLangURL 一字之差，英文页面的链接会跳回中文站；现在把「页面用 relLangURL、资源用 relURL」当成硬规则。
  • 加密页混进 sitemap：Hugo 默认的 sitemap 会把加密页的 URL 也列进去；后来用自己的 sitemap.xml 排除加密区，并在检查脚本里逐个语言扫一遍。
  • 解密后的图标：静态加密脚本用 document.write 换掉整个文档后，浏览器不会重新抓 <link rel=icon>，标签页会停在密码页的图标上；只能在解密完成后重新挂一次。

这些坑都不大，但每一条都对应一个「本地正常、线上不对」的下午。

如果重来一次

  1. 先想清楚站点是日记还是作品集。 两者的导航、首页、文章结构完全不同；混在一起，访客就找不到重点。
  2. 内容和排版分开。 把课程、项目、经历写成数据，模板只负责组合；否则每次改版都要重写一遍内容。
  3. 公开范围当成需求。 哪些给所有人看、哪些只给密码、哪些永远不公开，应该在搭站之前就决定。
  4. 迁移时做减法。 旧站的文章不是都要搬。该重写的重写，该私密的私密，该删的删；全部原样搬过去，只是把旧问题带进新站。

现在

第二版还在长。接下来想做的全站中文搜索、按年份的阅读时间线，以及把更多课程项目整理成可以复现的仓库——这些都需要时间，但至少现在的结构能接得住。

从 Solal2600 到 yicongl1，工具链几乎没变，变的是我终于知道这个站是给谁看的：给未来的雇主、老师和同学看，也给几年后的自己看。

这个站点本身记录在个人网站项目页里，那里有它的整体结构和相关文章。
