在 UNIX 课上写 Shell：sed、awk 与一个文件同步器

  • Linux
  • Shell
  • sed
  • awk
  • UNIX
对应课程 操作系统（SHU-23305502）

字体

字号

100%

LO03 是我第一次系统地用 UNIX。课分三块：Linux、Unix、系统，前面讲内存、进程、文件系统，后面全是命令行和脚本。每周的 TD 不是选择题，而是给你一个文件、一个需求，让你用 sed、awk、grep 把它做出来。

这门课最直接的影响，是我后来在 Linux 上排错时不再怕终端了。但它的作业也让我第一次意识到：Shell 写起来很快，写对很难。

从「一切皆文件」开始

课程的第一句话是 « tout est fichier »——所有东西都可以通过文件访问。用户信息在 /etc/passwd，密码哈希在 /etc/shadow，日志在 /var/log，设备在 /dev。理解了这一点，后面的大量操作就变成了「读一个文件、改一个文件」。

内存那一部分讲分页、MMU、页面替换（FIFO、LRU、时钟算法），进程那一部分讲 PCB、临界区、信号量。这些概念后来在别的地方反复出现，但当时最让我头疼的，还是每周的脚本作业。

几个当时写的脚本

1. 从名单批量建账号

题目给一个文本文件，每行两个名字，要求生成登录名、批量创建用户。当时的写法大概是这样：

#!/bin/bash
if [ $# -ne 1 ]; then
    echo "Usage : $0 fichier"
    exit 0
fi
if [ ! -r "$1" ]; then
    echo "Fichier <$1> inexistant"
    exit 0
fi

uid=1000
sed '/^#/d' "$1" | while read w1 w2
do
    ini1=$(echo "$w1" | cut -c1,2 | tr '[A-Z]' '[a-z]')
    ini2=$(echo "$w2" | cut -c1,2 | tr '[A-Z]' '[a-z]')
    login="$ini1$ini2"
    useradd -c "$w2 $w1 - TP ADMIN LINUX" \
            -d "/home/$login" -u "$uid" -s /bin/bash "$login"
    ((uid++))
done

它用到了 $#（参数个数）、$1（第一个参数）、test -r（可读）、sed 删注释行、cut 取前两个字母、tr 转小写。现在看，这段代码问题不少：

  • tr [A-Z][a-z] 如果不在外面加引号，方括号可能被 shell 当成通配符先展开；
  • while read 放在管道后面会跑在子 shell 里，循环里改的变量出了循环就没了；
  • useradd -u 1000 硬编码 UID，真实环境里很容易和已有用户冲突；
  • 密码那一行其实没设，-p 也没用上，建出来的账号是锁定的。

但当时它确实跑通了。看着 /etc/passwd 里一行行多出来，是我第一次觉得「脚本」这东西有实际威力。

2. 用 awk 算一张测量表

另一个作业是一张用 | 分隔的测量表：姓名、地点、日期、测量值、三次修正值、修正后的值。要求给修正值加上符号、计算修正后的总和与平均，并过滤掉格式不对的行。

BEGIN { FS="|"; OFS="|"; totale=0 }
NR>1 && NF>0 {
    $5 = -$5
    $6 = $6 + 0.1
    $8 = $4 + $5 + $6 + $7
    totale += $8
    n = split($3, tab, "/")
    if (tab[1] ~ /[0-3][0-9]/ && tab[2] ~ /[0-9][0-9]/ && tab[3] ~ /[1-2][0-9][0-9][0-9]/)
        print $0
}
NR==1 { print $0 }
END { printf "Totale des corrigees = %f\n", totale
      printf "Moyenne des corrigees = %f\n", totale/(NR-1) }

这段代码让我第一次理解 FS/OFS、NR/NF、BEGIN/END 分别是干什么的。但它也有明显的漏洞：日期正则只检查「两位数字」，99/99/9999 也能通过；NF>0 也挡不住空字段。如果重写，我会把日期拆成三段分别校验，而不是用一个宽松的正则糊过去。

3. 回文判断

同一个问题写了三个版本：rev 一行版、逐字符比较版、函数版。最短的是：

#!/bin/bash
if [ "$1" == "$(echo "$1" | rev)" ]; then
    echo "c'est un palindrome"
else
    echo "c'est pas un palindrome"
fi

但它只能处理一个参数。函数版要从文件里逐行读、再对每行的每个词调用一次，这才把 read、set、for、$? 串了起来。

文件同步器：题目与设计

课程最后有一个 Projet：写一个文件同步器，比较两棵目录树 A 和 B，用一个日志文件 ~/.synchro 记录上次同步成功的状态，根据「谁和日志一致、谁不一致」判断该往哪边复制；两边都改过就是冲突。

题目还要求做「内容比较」版本：如果两边修改得一模一样，就不该报冲突；如果内容相同但元数据不同，只需要同步元数据。

这个项目我做了，但源码现在找不到了，手边只剩题目 PDF 和一点笔记。所以这里只能按题目复盘设计，不能贴代码。

现在回看，这个题目其实很适合作为「系统编程入门」：opendir/readdir、stat、rename、utimensat，再加上一个清晰的决策表。它的难点不在算法，而在把「什么算冲突」这件事定义清楚。这一点和后来做数据同步、缓存失效时遇到的问题是相通的。

这门课留下的

  • Shell 是胶水，不是万能工具。 文本处理、批量重命名、定时任务，用 Shell 几分钟；一旦涉及二进制、并发、复杂状态，就该换语言。
  • 命令的返回值是控制流。 $?、&&、||、if test，Shell 的「异常处理」全在这里。
  • 引号决定一切。 变量、通配符、空格，绝大多数事故都能追溯到少写一对引号。
  • 项目要留代码。 文件同步器做过，但源码找不到了，现在只剩题目 PDF；如果当时把仓库留好，至少还能看到自己是怎么做的。

收获

UNIX 课给我的不是一堆命令，而是一种工作方式：先看数据长什么样，再决定用什么工具。sed 适合逐行替换，awk 适合按字段计算，grep 适合筛选，find 适合遍历——选对了工具，脚本自然就短。

至于那个同步器，我现在只记得设计思路，代码已经找不到了。这件事留下的教训很具体：做完的项目要留一个能找回来的仓库。
