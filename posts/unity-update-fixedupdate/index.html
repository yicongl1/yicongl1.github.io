Unity 入门：每帧循环与三个 C# 模式

    项目代码：https://github.com/yicongl1/Unity-Portfolio

    Unity 初学者最容易踩的坑之一，是把“读输入”和“动物理”写在同一个循环里。我的几个原型里都出现过这个问题，后来才慢慢分清 Update 和 FixedUpdate 的职责。这篇用项目里的三段代码说明。

    两个循环，两种时间

    • Update 每渲染一帧调用一次，间隔不固定，适合读输入、更新 UI、做与帧率无关的插值。
    • FixedUpdate 按固定的物理步长调用（默认 0.02 s），适合 Rigidbody、力和碰撞相关的计算。

    它们的调用次数并不一一对应：一帧可能执行 0 次、1 次或多次 FixedUpdate。所以：

    • 在 FixedUpdate 里用 Input.GetKeyDown 会漏输入（它只在某一帧为 true）；
    • 在 Update 里直接改 Rigidbody 速度，会让物理行为随帧率变化。

    变色跑酷：把输入存成标记

    变色跑酷里，按键在 Update 里读，动作在 FixedUpdate 里执行：

    public class PlayerCtrl : MonoBehaviour
{
    private bool jump;
    private bool changeColor;

    private void Update()
    {
        if (Input.GetKeyDown(Jump)) jump = true;
        if (Input.GetKeyDown(Change)) changeColor = true;
    }

    private void FixedUpdate()
    {
        pchar.Move(jump, changeColor);
        jump = false;
        changeColor = false;
    }
}

    这段代码的关键不是“分两个函数”，而是标记的生命周期：

    • Update 只负责把这一帧的按键翻译成意图；
    • FixedUpdate 消费意图，然后立刻清空；
    • 一次按键最多触发一次动作，不会因为这一帧跑了两次 FixedUpdate 而跳两次。

    这是最朴素的输入缓冲。更复杂的游戏会把标记换成队列（例如连招、冲刺），但思路一样：输入按帧采样，动作按物理步长消费。

    角色移动：方向、朝向、位移

    角色移动 Demo 里没有 Rigidbody，直接在 Update 里改 transform：

    void Update()
{
    float h = Input.GetAxis("Horizontal");
    float v = Input.GetAxis("Vertical");
    Move(h, 0, v);
}

void Move(float x, float y, float z)
{
    move = new Vector3(x, y, z);

    if (move.sqrMagnitude > 0.0001f)
    {
        Vector3 to = transform.position + move;
        transform.LookAt(to); // 目标点，不是方向向量
    }

    transform.position += move * speed * Time.deltaTime;
}

    两个细节值得记：

    1. LookAt 接收的是世界坐标中的目标点，所以要先 position + direction；直接把方向向量传进去，角色会看向原点附近。
    2. 位移乘 Time.deltaTime，否则速度会随帧率变化；而 sqrMagnitude 比 magnitude 少一次开方，用来判断“有没有输入”足够。

    迷宫滚球：力的调用位置

    同一个项目里的迷宫小游戏用的是力：

    void Update()
{
    float x = Input.GetAxis("Horizontal");
    float z = Input.GetAxis("Vertical");
    Vector3 f = new Vector3(x, 0, z);
    r.AddForce(f * 5);
}

    它能跑，但有两个问题：

    • AddForce 写在 Update 里，施加频率随帧率变化，帧率越高推力越大；
    • 每一帧都叠加一次力，没有“松开就停”的阻尼，球会越滑越快。

    如果重做，我会把它挪到 FixedUpdate，并改成“目标速度 + 加速度”的写法，而不是无限叠加力。这也是我在这个项目里最想回头改的一段代码。

    什么时候用哪个

    • 读输入、UI、相机跟随、纯视觉插值 → Update
    • Rigidbody 的速度、力、碰撞参数 → FixedUpdate
    • 需要“按帧触发一次”的输入 → 在 Update 里存标记，在 FixedUpdate 里消费

    分清这两个循环之后，很多“跳跃偶尔失灵”“移动速度忽快忽慢”的问题会自然消失。

    三个从 C# 练习带过来的模式

    作品集里还有 8 个 C# 控制台练习。它们看起来和游戏无关，但其中三个模式后来直接搬进了 Unity 项目。

    单例：只留一个 GameMode

    变色跑酷需要一个地方统一处理死亡、重开和退出：

    public class GameMode : MonoBehaviour
{
    public static GameMode Instance { get; private set; }

    public void Awake() => Instance = this;

    public void OnPlayerDie()
    {
        if (Panel != null) Panel.gameObject.SetActive(true);
    }
}

    玩家脚本不用在 Inspector 里拖引用，直接 GameMode.Instance.OnPlayerDie()。代价是全局状态，测试和复用更难，所以我只把它用在真正全局、且生命周期跟随场景的管理器上。

    加权随机：把权重铺成一条线段

    抽卡练习里，每张卡按权重占比被抽中：

    int seed = Random.Range(0, powersum);
for (int i = 0; i < cards.Count; i++)
{
    seed -= cards[i].power;
    if (seed <= 0) return cards[i];
}

    总长度是 powersum，每张卡占 power 长度，随机落点落在谁身上就是谁。不需要浮点概率，也没有精度问题。

    回合制状态：伤害公式与安全删除

    回合制练习里的伤害用饱和曲线，防御再高也减不到 100%：

    float attackActual = attack * (cent / 10000f);
int damage = (int)(attackActual * (1 - (float)def / (300 + def)));

    持续治疗/中毒则存进 states 列表，到期删除：

    for (int i = 0; i < states.Count; i++)
{
    if (states[i].time == 0)
    {
        states.RemoveAt(i);
        i--;   // RemoveAt 会让后面的元素前移
    }
}

    i-- 是关键——少了它就会跳过紧跟在被删元素后面的那个状态。这个坑和游戏里的对象池、Buff 列表是同一个问题。
